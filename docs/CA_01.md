## Architecture and user flow

Normal conversation enters `ChatService` and `CodingBridge`. `codingIntent.ts` classifies narrow local actions; ordinary conversation stays on the approved Gemma digest. Repository names are matched against discovered Git repositories under `C:\Users\karlr\repos`. Main-process `CodingAgent` is the sole task engine. Chat and Coding workspace read its same IPC snapshot. Tool events render separately from messages.

For an existing repository, Astra selects it, reads indexable source and guidance as untrusted context, and asks the installed `qwen2.5-coder:7b` for a JSON proposal. The existing model router uses the recorded Intelligence V1 score of 5/6 as preliminary permission for bounded proposals, not proof of unattended coding reliability. `codingModel.ts` enforces a schema, two attempts, a 90 second attempt timeout, listed files only, and unique exact-match hunks. It never accepts command text from model output. The proposal lists objective, selected repository, cause as an inference, exact patch, files, test command, outcome, risks, and optional task branch. Karl can inspect the patch in Coding and approve/reject in chat or Coding. Approval binds repository, files, command array, branch, patch, and scaffold. Main then applies the approved patch, runs the approved command without a shell, reviews Git's diff, and records the result. A failed check is reported as failed; it is never called a pass.

For a new repository, chat proposes an exact path and local scaffold. The React and TypeScript scaffold declares React, types, TypeScript and Vite versions, but does not install them. Approval creates only the named directory under the root, writes exactly the approved files, initialises local Git, and shows Git's diff against an empty file for the initial untracked files. Any existing destination is refused. No remote is created.

`CodingAgent` records plans, approvals, changes, tests and state transitions in SQLite. On restart, unfinished tasks require confirmation and fresh plan approval. No executable work resumes automatically. Task history and prior events are available in Coding. Cancellation withdraws approval, aborts an active command, waits for process exit, then reports cancellation. The shell-free runner invokes Windows npm through its local `npm-cli.js` via Node; installation remains denied. Command output is bounded and common secret forms are redacted before persistence.
